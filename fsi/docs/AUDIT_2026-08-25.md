# Audit Technique — 25 Août 2026

Audit complet du modèle : chasse aux bugs, revue de sécurité, renforcement
des tests. Méthode : balayages automatisés (lint, sorties non échappées, SQL
brut, superglobales), lecture ligne à ligne des fichiers à risque
(`ResourceController` 1 677 lignes, `UserController`, `PostController`,
`MessageController`, `ContactController`, `MediaService`, `SiteScopedModel`,
`SiteResolverService`, `AdminAccessService`, `HomePageService`,
`PublicPageController`, filtres et routes), puis vérification empirique de
chaque suspicion avant correction.

## Bugs Corrigés

### 1. Redirection ouverte partielle — `LanguageController` (moyen)

`safeRedirect()` comparait le paramètre `redirect` au baseURL **sans slash
final** : `https://host:port.malveillant.example` passait le contrôle de
préfixe. Corrigé en comparant contre le baseURL **avec** son slash final ;
un hôte voisin est désormais rejeté vers l'accueil.

- Régression : `FoundationRoutesTest::testManualLanguageSelectionPersistsAndRejectsOpenRedirects`
  (cas lookalike + cas absolu légitime sur le même hôte).

### 2. Erreur 500 possible sur `/formations` avec données hors référentiel (faible)

`PublicPageController::programmes()` écrivait dans `$grouped[$programme->level]`
sans garde : un niveau inconnu (donnée importée/éditée hors validation)
levait une erreur sur une page publique. Désormais les niveaux hors
référentiel sont ignorés silencieusement.

- Régression : nouveau `PublicProgrammeLevelGuardTest`.

### 3. Limite de débit du contact uniquement par e-mail (moyen)

Un expéditeur pouvait contourner la limite de 120 s en changeant d'adresse
électronique à chaque envoi (bombardement de la boîte + des notifications
SMTP). Ajout d'une seconde limite **par adresse IP** : 20 messages/heure.
Les deux limites s'appliquent cumulativement.

- Régression : nouveau `ContactIpRateLimitTest` (blocage au seuil,
  non-blocage des autres visiteurs ; utilisation de
  `service('superglobals')->setServer('REMOTE_ADDR', …)` car la requête de
  test lit le snapshot, pas `$_SERVER`).

## Suspicions Vérifiées Non Coupables

| Suspicion | Verdict |
|---|---|
| CRUD multi-site non scopé (`delete`/`restore`/`purge` par id) | Sûr : chaque action passe d'abord par un `find()` scopé par `forSite()` ; les écritures directes ne sont atteignables que si l'enregistrement appartient au site actif |
| `is_unique[table.field]` cassé sous préfixe de base | Faux positif : `BaseBuilder` préfixe automatiquement les noms de tables (vérifié : `tableExists('users')`=oui, tables réelles `test_*`) |
| Jointures littérales (`auth_identities`) cassées sous préfixe | Faux positif, même raison |
| Fuites cross-site sur les listes publiques | Aucune : tous les appels publics passent par `forSite()` ; `PostModel::visible()` scope lui-même |
| Escalade de privilèges via `POST /admin/users` | Impossible : groupes/permissions/sites forcés côté serveur pour les non-superadmins + double contrôle des valeurs postées + verrous anti-auto-lockout et dernier-superadmin |
| Injection d'en-têtes via le formulaire de contact | Protégé : normalisation mono-ligne + validation e-mail + ReplyTo validé + sujet nettoyé |
| Uploads malveillants | Solide : extension + MIME réels + `getimagesize`, noms aléatoires, dossier contraint `[a-z0-9_-]`, suppression avec garde anti-traversée (`realpath`) |
| XSS vues | Aucune sortie non échappée détectée (balayage exhaustif) |
| Déconnexion GET | Shield enregistre bien la route GET `logout` |

## Points Notés Sans Changement (décision documentée)

1. **Mots de passe sans plafond de longueur** : bcrypt tronque à 72 octets
   silencieusement ; un `max_length[72]` améliorerait l'honnêteté UX mais
   casserait des comptes existants plus longs. À traiter lors d'une future
   évolution assumée.
2. **Re-publication d'une actualité** remplace `published_at` par « maintenant » :
   comportement discutable mais cohérent avec l'UX actuelle.
3. **Écriture des traductions EN hors transaction** après le contenu FR :
   un échec SMTP-like laisserait la traduction absente sans erreur visible ;
   impact faible (le fallback français s'applique).
4. **En-têtes géo (`CF-IPCountry`…)** falsifiables : ne influence que la langue
   publique par défaut, aucun risque sécurité.
